# 公司模拟生产测试交接

开发侧在本地完成构建和模拟验证。接收方使用公司已有的模拟生产平台，确定执行人、测试区和允许变更的范围。先选定一个原业务客户端及服务端版本、一款 UKey 和一套终端环境。对现有网页保留入口、插件、助手版本和配置，施工和回滚前后均安排网页回归。

| 交接阶段 | 执行人 | 操作及输出 |
|---|---|---|
| 交付基线 | 开发 | 提供本包、SHA-256 和本地报告。用 `baseline/` 区分已通过的检查和已知缺口。 |
| 平台复现 | 有权限的接收方 | 在公司允许的测试节点运行 `doctor` 和 `quick`，记录系统、架构、Java、Python 版本，回传 `acceptance-result.json` 或启动阻塞原因。平台有专门的包导入方式时，按其规则部署随包 JAR。 |
| 真实环境摸底 | 接收方会同业务厂商或运维 | 用真实客户端跑业务基线，收集连接清单，使用厂商支持的方式验证测试 UKey 和证书。填下表，提供脱敏结果及对应接口文档。 |
| 真实组合联调 | 接收方和开发 | 确认适配实现和版本后，在批准的测试区执行真实接入、拒绝、共存和回滚用例。保留版本、操作记录和证据。 |

首轮回传包含包名和摘要、测试任务编号或内部记录位置、执行环境、实际结果和阻塞项。若缺少运行时、测试设备、厂家接口或权限，请记录具体缺项和对应责任人。测试账号、PIN、私钥和公司平台访问凭据通过公司指定方式保管。

## 麒麟 x86 首轮检查

记录麒麟的桌面版或服务器版、具体版本及补丁、CPU 架构和机器角色。先在公司指定节点用普通测试账号执行下列命令。已有多个 Java 版本时，可以给 `doctor` 和 `quick` 加上 `--java-home` 指定获准使用的 Java 17+ 目录。

```sh
cat /etc/os-release
uname -m
uname -r
getconf LONG_BIT
java -version
command -v keytool
python3 --version
python3 test.py doctor
python3 test.py quick
```

| 现场情况 | 需要实测的内容 |
|---|---|
| 麒麟只承担接入服务或网关 | 检查相应架构的 Java、Python、运行目录写入和回环端口权限。确认终端、网关和业务服务器之间的批准连接，核实证书信任与时间同步。 |
| 麒麟也是用户终端 | 用目标客户端实际登录并跑代表性操作。核实 UKey 厂商支持这一麒麟版本及架构，并实测设备识别、证书、PIN 和签名或握手。 |
| 在虚拟机上使用实体 UKey | 先确认公司平台是否提供 USB 透传及设备权限，再用厂商工具验证实际连接到该测试虚拟机。 |
| 厂家组件需要加载本地库 | 确认被加载的库和调用进程的架构及位数匹配，并检查厂商列出的系统库和驱动依赖。 |
| 测试区限制网络操作 | 本机 DEMO 使用回环端口。三网区脚本需要 Linux 网络命名空间、虚拟网卡、限速与丢包模块以及相应权限，按公司批准的环境执行。 |

当前交接包的本机测试已在 macOS 和 Debian arm64 上运行。麒麟 x86 结论由接收方实测补齐。首次回传系统与运行时版本、`acceptance-result.json` 或启动报错。实体 UKey 和原业务的兼容性单独记录。

| 要确认的内容 | 现场记录 |
|---|---|
| C/S 客户端、服务端版本，测试账号与业务负责人 | 待填写，凭据单独交接 |
| 终端系统、位数、安装权限和共享工作站情况 | 待填写 |
| UKey 型号、固件、驱动或助手版本，签名或通道接口 | 待填写 |
| 证书用途、信任链、吊销查询与密钥管理责任 | 待填写 |
| 业务连接目的地址、端口、协议、备用路径与代表性业务操作 | 待填写 |
| 网关、客户端或密码产品版本，适用的证明材料和配置 | 待填写 |
| UKey 身份对应实际业务账号的受支持实现 | 待填写 |
| 网页共用的业务服务、终端、网络与密码组件 | 待填写 |
| 可调整的网络规则，允许中断时间与回滚方式 | 待填写 |
| 被测系统范围、适用密评指标和取证负责人 | 待填写 |

按以下顺序记录操作、预期、实测、结果和证据位置。

1. **业务基线**。用原客户端在隔离环境跑完登录和代表性操作，记录涉及的全部连接。确认原业务是否支持配置地址或厂商认可的接入方式。
2. **真实 UKey**。用测试设备核对枚举、证书用途、PIN、签名或握手。记录选定适配的组件版本，按设备策略验证错误 PIN、无 Key、失效和吊销。
3. **受控访问**。在选定通道验证身份、资源和实际业务账号关联。使用有效业务密码测试未经授权直连、备用入口和同机其他用户。核对退出、换班、拔 Key、断线和恢复。
4. **网页共存**。比较部署前后网页入口、配置和登录结果，检查共用终端交替使用设备时的行为。
5. **运维和证据**。由现场运维独立安装、升级、排障与回滚。按适用指标保存拓扑、产品版本、规则、密码保护范围和实测证据，测试报告使用脱敏数据。

随包的 `demo/config/pilot-support.template.properties` 可作为支持矩阵补充。当前二进制只支持 DEMO，真实模式会拒绝启动。现场需要选定并验证硬件身份及通道适配，才能运行真实组合。测试结论分别记录网络接入、应用身份、链路保护、运维和密评证据，保持各自的范围。
