# 管理平台发布恢复后如何接入

## 目前模拟的部分

`--mode mock` 在本机为每次启动创建独立的助手替身、管理规则/验签替身、登录绑定服务和 TCP 样例业务。管理规则是 `alice → MOCK-KEY-001`、`bob → MOCK-KEY-002`；模拟助手仅提供第一支设备，因此 Bob 会被拒绝。

模拟签名采用运行时随机密钥的 HMAC-SHA256，**不是 SM2、不是证书认证，也不调用真实硬件**。它用于让篡改、失败、重放和过期测试有可检查的结果，不模拟管理平台的部署界面或宣称 `/deploy` 已成功。

## 与现有网页登录插件保持一致的接口

已对照 `web-plugin/reference/main-interceptor-all.js`，保留以下调用契约：

| 调用方 | 方法及路径 | 请求与判定 |
|---|---|---|
| 桌面端 → 本机助手 | `POST /sys/getDevInfo` | 表单，读取 `code=200`、`SerialNumber` |
| 桌面端 → 本机助手 | `POST /sys/verifyPin` | 表单字段 `pin`，仅接受 `code=200`，失败不重试 |
| 桌面端 → 本机助手 | `POST /sys/signwithpid` | 表单 `plainData`、`plainDataLen`，读取 `signData`；长度与 JS 的 UTF-16 长度一致 |
| 新绑定服务 → NMR | `GET /verifyUser?username=…` | 只接受 JSON 布尔 `true` |
| 新绑定服务 → NMR | `GET /genRandom?serialNumber=…` | 原样保留响应文本，交给设备签名 |
| 新绑定服务 → NMR | `POST /verifySign` | JSON：`plainText`、`originalText`、`signResult`、`signature`、`serialNumber`、`username`；仅接受文本 `true` |

桌面端不接收密码服务 SDK 的访问密钥。真实验签交由 NMR 现有密码服务路径完成；证书、设备和账号绑定的正确性仍需在发布恢复后联调。

## 为什么不直接连接管理平台页面

管理平台的 `/nmrapi/platform/deploy` 用于下发配置，不是终端的登录认证接口。终端应使用**已经发布配置的 NMR 插件实例**。本实验没有伪造未知的管理平台登录凭据或发布请求。

真实模式必须明确指定 `--app-id` 与 `--nmr-url`。旧 NMR 三个认证接口本身没有应用 ID 参数，且其配置按实例发布；因此恢复联调前，要确认该 NMR 实例绑定的就是指定平台应用。代码只在新服务端校验本次请求的应用 ID，不能自动证明管理平台实例配置一致。

网页旧逻辑中 `verifyUser=false` 可能表示豁免，也可能是配置缺失。**新增实验只测试强制 UKey 登录，false 一律阻止，而不是跳过 PIN。** 这个条件只用于新流程，旧网页代码没有改变。

## 新服务端增加的登录绑定

1. 挑战登记绑定应用、业务账号、设备、原文与 60 秒期限。
2. 证明只尝试一次；验签失败或上游失败不恢复挑战。
3. 验签通过后签发同一记录绑定的一次性业务授权；其期限不会重新延长。
4. 本机受控业务入口先消费授权并核对应用/账号，再向样例业务提交原账号密码。
5. 取消撤销挑战及关联授权；过期授权和重复提交均不能访问受控入口。

PIN 不发往 NMR、新绑定服务或样例业务，不写文件和日志。真实助手仅允许本机地址；本地调用显式禁用环境 HTTP 代理。GUI 的“取消”在确认 PIN 前有效；点击“验证并继续”后等待本次提交结果，不宣称能够撤回已执行的业务登录。

## 恢复真实联调的条件

- 管理平台发布成功，目标 NMR 已收到应用及 UKey 用户配置。
- 目标账号、设备序列号和签名证书绑定正确，NMR 的随机数/验签所需密码服务可用。
- 设备持有人在真实模式 PIN 窗口输入 PIN；不向聊天或脚本提供真实 PIN。
- 先验证正确 PIN 的签名与验签，再验证取消和服务失败时不提交业务登录。不自动测试错误 PIN，避免设备锁定。

无需重写桌面流程：切换为 `--mode nmr` 并提供明确地址和应用即可进入真实接口路径。接口契约已用本地替身测试，现场证书与算法互操作尚未验证。若管理平台继续不可用而需要真实设备离线测试，应先取得对应签名公钥证书和明确的 SM2 用户 ID/签名编码，不能把“返回了 signData”当作验签成功。

本轮没有部署防绕行、OS 进程隔离或生产 TLS。真实部署时还需为新授权入口选择可信传输、原业务协议适配及原入口访问限制；不要把本机 HTTP 实验端口开放到外网。
